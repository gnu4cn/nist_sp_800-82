# 保护技术（PR.PT）

技术机制可协助组织保护其环境中的设备和信息。随着威胁的演变和变化，仅靠这些技术可能不足以维持安全能力。因此，组织应按照政策、程序和协议的要求，对保障组织资产安全的技术解决方案进行管理。

## 日志记录 (PR.PT-1)

日志记录使组织能够捕获其系统和网络中发生的事件。这些事件可能由多种不同的系统生成，包括

- 操作系统、
- 工作站、
- 服务器、
- 网络设备、
- 网络安全软件、
- 和应用程序。


相关补充指南，可参见以下文档：

- NIST SP 800-92，*[《计算机安全日志管理指南》](https://doi.org/10.6028/NIST.SP.800-92)*。


> **特定于运营技术（OT）的建议与指南**
>
> 捕获日志事件对于保持对运营技术系统的态势感知至关重要。典型的事件包括
>
> - 维护功能。例如访问控制、配置更改、备份和恢复；
> - 操作系统功能；
> - 以及应用程序（即进程）事件。
>
>
> 可供记录的具体事件类型，因运营技术设备而异，应根据设备的功能以及需要捕获的事件进行选择。
>
> 为支持日志关联分析，每条日志条目应明确标识
>
> - 生成该事件的设备、
> - 事件的时间戳，
> - 以及生成该事件的用户或系统账户。
>
>
> 一般而言，每条日志条目还应包含事件发生的位置、事件类型、发生时间、事件来源、与事件相关的用户或系统账户身份，以及事件的结果。
>
> 当设备生成的事件时间戳未基于共享的时间源时，则难以在多个 OT 设备之间关联事件。每个设备的内部时钟都应与主时钟保持同步，以支持设备间的事件关联。日志条目还应采用一致的时间戳格式，例如时区格式、字符串格式、夏令时设置。
>
> 日志收集和事件转发功能可能会影响 OT 设备的性能。根据日志记录事件的频率，日志大小可能会迅速增长，导致空间占用增加。大多数 OT 设备的磁盘空间和内存都有限，因此应提供足够的本地或远程存储空间，以降低超过设备容量的风险，否则最终可能导致日志记录功能丧失。应考虑将日志从 OT 设备传输到备用存储设备。
