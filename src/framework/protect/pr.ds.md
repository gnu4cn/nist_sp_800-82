# 数据安全（PR.DS）

提供数据安全，包括保护静态数据和传输中数据的机密性、完整性和可用性，保护已移除的资产，以及防止数据泄露。

密码学可满足数据安全要求。可利用加密、数字签名、哈希及其他密码学功能，防止对静态数据和传输中数据进行未经授权的访问或篡改 【[RFC4949](../../refs.md#rfc4949)】。在选择密码学方案时，组织应使用经过认证的密码系统。联邦组织必须遵守 FIPS 140-3 【[FIPS140-3](../../refs.md#fips140-3)】 标准，及 [密码模组验证计划，Cryptographic Module Validation Program, CMVP](https://csrc.nist.gov/projects/cryptographic-module-validation-program)。此外，应保护密码硬件免受物理篡改，以及不受控的电子连接的影响。

有关数据安全的补充指南，请参阅以下文件：

- NIST SP 800-47，第 1 版，*[《信息交换安全管理》](https://doi.org/10.6028/NIST.SP.800-47r1)*；
- NIST SP 800-111，*[《终端用户设备存储加密技术指南》](https://doi.org/10.6028/NIST.SP.800-111)*；
- NIST SP 800-209，*[《存储基础设施安全指南》](https://doi.org/10.6028/NIST.SP.800-209)*。


> **特定于运营技术（OT）的建议与指导**
>
> 确定需要保护的静止状态下的关键物理文件和电子文件类型及数据。这可能包括个人身份信息，以及敏感、专有或商业秘密信息，例如：
>
> - PLC 程序代码、
> - 机器人程序、
> - 计算机辅助设计（CAD）或计算机辅助制造（CAM）文件、
> - 操作手册和文档、
> - 电气图、
> - 网络图、
> - 历史生产数据等。
>
> 【[IR8183A](../../refs.md#ir8183a)】
>
> 组织应考虑将关键数据集中存储于安全的存储位置。
>
> 当 OT 数据存储在云端或供应商服务器上时，组织应考虑进行风险分析，以确定服务提供商如何保护这些数据，以及是否应实施额外对策，将风险控制在可接受的水平。
>
> 监控从 OT 安全域流向其他安全域的信息流，以及安全域之间的连接。可采用数据二极管、防火墙和访问控制列表 ACL 等技术，来限制信息流。关键接口和互连的示例可能包括 IT 与 OT 之间、OT 与外部行业合作伙伴之间，或 OT 与第三方支持供应商之间的接口。
>
> 为保护报废系统组件上的数据，应实施资产处置计划，其中包括在处置前对关键数据和介质进行擦除、净化或以其他方式销毁的考虑。资产处置计划应涵盖所有可移除介质、移动设备及传统 OT 硬件。
>
>
> **加密**
>
> 关键 OT 数据在传输过程中应受到保护，尤其是在经过第三方网段以及其他不可信或存在漏洞的网络路径，例如蜂窝网络、无线网络、互联网、广域网时。应识别关键数据，并实施加密机制，例如加密，以防止系统数据和审计记录遭到未经授权的访问或篡改。加密提供了一种机制，用于确保传输中数据的机密性和完整性。
>
> OT 应用程序通常侧重于数据的可用性。在 OT 环境中部署加密之前，应确保应用该安全控制的目标是机密性或完整性。在 OT 环境中使用加密可能会引入通信延迟，因为加密、解密和验证每条消息，都需要额外的时间和计算资源。加密还可能导致终端设备或系统的性能下降。在 OT 环境中部署加密之前，应测试解决方案以确定延迟是否在应用程序可接受的范围内。可采用 OSI 第 2 层而非第 3 层加密，以帮助降低加密延迟。
>
> 此外，虽然加密能在加密设备与解密设备之间确保机密性，但支持 OT 环境的异常检测工具，可能无法读取加密数据。因此，应谨慎规划和实施加密措施，以管控运营风险。
>
> 组织还应考虑到，加密技术可能会引发密钥管理问题。健全的安全策略，需要完善的密钥管理流程，而随着 OT 地理范围的扩大，这一工作可能会变得更加困难。由于前往现场更换或管理密钥可能成本高昂且耗时，组织应考虑采用支持远程密钥管理的加密保护方案是否更为有利，例如当受保护的设备数量庞大或地理分布广泛，导致密钥管理变得困难或成本高昂时。
>
> 对于 OT，加密可作为全面且强制执行的安全策略的一部分进行部署。加密密钥的长度应足够长，以确保通过猜测或分析确定密钥所需的精力、时间和成本，高于受保护资产的价值。
