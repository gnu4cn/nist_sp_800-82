# 远程访问

应实施远程访问安全控制措施，以防止对组织的网络、系统和数据的未经授权的远程访问。虚拟专用网络 VPN 属于一套旨在支持安全远程访问网络环境的协议。VPN 通过在公共基础设施上建立一个作为叠加层运行的私有网络，既能提供强身份验证又能提供加密，从而保障通信数据的安全。最常见的 VPN 技术类型包括：

- **互联网协议安全 IPsec**。IPsec 支持两种加密模式：传输模式和隧道模式。传输模式仅对每个数据包的数据部分（即有效载荷）进行加密，而数据包头保持不变。安全性更高的隧道模式，则为每个数据包添加一个新头部，并对原始头部和有效载荷同时进行加密。在接收端，符合 IPsec 标准的设备会对每个数据包进行解密；
- **传输层安全协议 TLS**。TLS 有时也被称为其旧称 “安全套接字层”（SSL），他能在两台机器之间建立一个安全通道，并对每个数据包的内容进行加密。TLS 最广为人知的作用是，通过一种称为 “安全超文本传输协议”（HTTPS）的协议实现，来保障超文本传输协议 HTTP 流量的安全。然而，TLS 并不局限于 HTTP 流量，也可用于保障许多应用层程序的安全。应仅考虑使用 TLS 1.2 或更高版本；
- **安全外壳协议 SSH**。SSH 属于一种用于安全访问远程计算机的命令行界面和协议。网络管理员广泛使用他来远程控制基于 Linux 的服务器。SSH 是 telnet 应用程序的安全替代方案，包含在大多数 UNIX 发行版中，通常可通过第三方软件包添加到其他平台。

- NIST SP 800-63B，*[《数字身份指南：身份验证与生命周期管理》](https://doi.org/10.6028/NIST.SP.800-63b)*；

> **特定于运营技术（OT）的建议与指南**
>
> 许多运营技术（OT）安全架构均采用多层设计，例如普渡模型。这种设计可以显著限制访问权限，从而最大限度地减少对运营造成的意外或未经授权的中断。应制定并向组织传达关于申请和启用远程访问的流程。仅在有正当理由的情况下才应提供远程访问，且访问范围应仅限于业务需求所必需的范围。远程访问不应规避，或削弱安全或安保控制措施。对 OT 系统的远程访问，应考虑采用多因素身份验证。
>
> 在紧急情况下或需要供应商支持时，可能会申请临时远程访问以进行维护。在此类情况下，仍应遵循相关流程，以确保使用安全的连接。
>
> 实现临时远程访问有多种不同的技术手段，包括：
>
> - 通过运营技术（OT）或企业防火墙临时允许的用户或协议（例如 RDP、SSH）；
> - 屏幕共享技术；
> - 调制解调器;
> - VPN。
>
> 无论采用何种技术，组织都应考虑以下几点：
>
> - 设置唯一的用户名和复杂的密码；
> - 删除、禁用或修改任何默认凭据；
> - 将所有软件和固件更新至最新版本；
> - 在不再需要时撤销访问权限。可考虑实施自动定时器来撤销访问权限，或通过变更管理流程，手动确认访问权限的撤销；
> - 监控远程活动；
> - 确保运维人员知晓运营技术（OT）环境中的计划远程活动；
> - 从运营技术（OT）环境发起连接；
> - 对远程连接设备进行标识，以便在发生未经授权使用时，运维人员能够迅速断开连接。
>
>
> **拨号调制解调器**
>
> 当在 OT 环境中使用拨号调制解调器时，请考虑采用回拨系统。该系统通过让调制解调器根据拨号者的信息，以及存储在 OT 批准的授权用户列表中的回拨号码建立工作连接，从而确保拨号者是授权用户。
>
> 在可行时，要在不使用时断开调制解调器的连接，或者考虑通过设置调制解调器在运行一定时间后自动断开连接，从而实现断开过程的自动化。有时，调制解调器连接属于与供应商签订的法律支持服务协议的一部分（例如，提供响应时间为 15 分钟的 7×24 小时支持）。相关人员应知悉，断开或移除调制解调器可能需要重新协商合同。
>
> **VPN**
>
> 用于保护 OT 系统的 VPN 设备应经过全面测试，以验证 VPN 技术与应用程序兼容，且 VPN 设备的部署不会对网络流量特性产生负面影响。
>
> VPN 技术也可应用于网络分段之间。例如，远程站点可能配备现场边界保护设备，该设备利用 VPN 在不可信网络（例如互联网）上建立安全隧道，连接到位于不同位置的主控制中心中，支持 VPN 的设备。
