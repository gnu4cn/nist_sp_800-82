# 附录 C, 威胁来源、漏洞与安全事件

数个术语被用于描述威胁、威胁源、威胁事件和事故等相互关联的概念。所谓 *威胁*，是指可能通过信息系统通过未经授权的访问、破坏、披露、修改信息和/或拒绝服务，对组织运营（包括使命、职能、形象或声誉）、组织资产、个人、其他组织或国家，产生不利影响的任何情况或事件。威胁具有某种意图或方法，可能通过有意或无意的方式利用漏洞。这种意图或方法称为 *威胁源*。所谓 *漏洞*，是信息系统（包括 OT）、系统安全程序、内部控制措施或实施中，可能被威胁源利用或触发的弱点。所谓 *威胁事件*，是有可能导致不良后果或影响的事件或情况。当威胁事件发生时，他就成为实际或潜在危害信息系统或系统处理、存储或传输的信息的机密性、完整性或可用性的事件，或者构成违反安全策略、安全程序或可接受的使用策略的违反或迫在眉睫的威胁。

这个附录探讨了特定于 OT 的威胁源、漏洞和事件。他还引用了 OT 特定事件的示例，来说明其潜在影响。每个组织都会根据其环境中的特定威胁、漏洞、影响和事件的可能性，来计算风险。

## 漏洞和诱发条件

所谓 *漏洞*，是信息系统、系统程序、控制或实施中可被威胁源利用的弱点。所谓 *诱发条件*，是导致威胁事件发生可能性的组织、任务或业务流程、架构或信息系统的属性。这些漏洞和诱发条件的顺序，并不反映发生可能性，或影响严重程度的优先级。此外，这一小节中确定的漏洞和诱发条件，不应被视为完整列表，也不应假设他们发生在每个 OT 环境中。

漏洞和诱发条件会根据其存在位置加以分组，例如在组织的政策和程序中，或者在硬件、固件和软件中实施的安全机制的不足。前者称为在组织内，后者称为在系统内。了解漏洞的来源和诱发条件，有助于确定最佳的缓解策略。更深入的分析可能会发现，原因和观察结果可能不是一对一的 —— 也就是说，一些根本原因可能会表现出多种症状，而一些症状可能来自多个原因。

任何特定的运营技术（OT）系统，通常会存在这一附录中已识别漏洞的一部分，但也可能包含某些特定技术或实现方式所特有的其他漏洞和易受攻击因素。有关运营技术漏洞的具体最新信息，可查阅 [CISA 网站](https://www.cisa.gov/uscert/ics/advisories)，尽管许多供应商发布的通知和补丁并不总能在 CISA 网站上找到。与供应商保持联系，有助于及时掌握已知漏洞的最新动态。

部分漏洞和诱发条件可通过缓解措施加以控制。而另一些漏洞则只能通过采取适当的应对措施加以接受和控制，但这将导致运营技术环境存在一定的残余风险。例如，对于某些现有政策和程序，组织可在其认为可接受的投入范围内进行调整；而对于其他情况，则通过制定新的政策和程序，来更迅速地加以处理。

从组织外部采购的产品和服务中的漏洞，通常很少处于组织的直接控制之下。市场力量可能影响这些变化，但这是一种缓慢且间接的方法。相反，组织可以通过改变诱发条件，来降低系统性漏洞被利用的可能性。

### 政策与流程中的漏洞及诱发因素

由于安全政策，包括文档、实施指南（例如流程）及执行措施等存在不完善、不恰当或缺失的情况，漏洞和诱发因素往往会引入到运营技术（OT）环境中。管理层对安全政策和流程的支持，是任何安全计划的基石。组织的安全政策可通过强制要求并执行恰当的行为，来降低漏洞风险。书面政策和程序是向员工及利益相关方，传达有益于组织的行为决策的机制。从这一角度看，政策属于一种通过教育和指导，来降低漏洞风险的方式。执行是政策的补充，能鼓励人们采取正确行动。对于不遵守政策和程序的人员，通常会采取各种形式的纠正措施。政策应明确规定对不遵守者（个人或组织）的后果。

通常存在一个复杂的政策与程序环境，其中包含法律、法规、相互重叠的管辖权和影响力范围、经济因素、习俗以及历史背景。大型企业通常被划分为多个组织单元，这些单元应协同合作，以降低安全漏洞。为了实现最大效用，必须对政策与程序的范围及其层级关系进行管理。

下 [表 14](#t-14) 列举了观察到的政策和程序漏洞，以及针对 OT 的诱因。

| 关键组件缺乏冗余 | 关键组件缺乏冗余可能会导致单点故障。 |


### 系统漏洞与诱发因素

安全控制措施必须明确界定其适用的系统范围。系统的规模、范围和能力差异巨大。在系统规模的较小一端，一个系统可能仅是一个单独的硬件或软件产品，或是某项服务；而在另一端，则是大型复杂系统、系统集群以及网络，这些系统均集成了硬件架构和软件框架（包括应用程序框架）以支持其运行。组织可选择划分安全区域，以便将安全控制措施应用于该安全区域内的所有系统。

用于构建运营技术（OT）的硬件、固件和软件中均可能存在系统漏洞。漏洞的来源包括设计缺陷、开发缺陷、配置错误、维护不善、管理不善，以及与其他系统和网络的连接。NIST SP 800-53 中的许多控制措施，以及 [附录 F](./appendix-f.md) 中的 OT 叠加层，都规定了系统必须采取哪些措施来缓解这些漏洞。

支持 OT 系统的辅助组件中也可能存在漏洞。这一小节描述了其中可能影响物理过程的一类漏洞。

| 供应商拒绝开发漏洞补丁 | 过时的操作系统和应用程序，可能包含新发现的可被利用的漏洞。旧版 OT 可能无法提供安全补丁支持，因此漏洞管理程序应包括用于缓解补丁可能永远不可用的漏洞的应急计划或替换计划。 |
| 缺乏漏洞管理计划 | 组织未考虑的漏洞可能会导致被利用。应制定漏洞管理程序，以确定发现漏洞后采取行动或不采取行动的计划。一些 OT 考虑因素包括： 可用性问题可能会将修补程序推迟到下一次计划的运营停机时间；使用过时操作系统的 OT 系统，可能无法获得安全补丁支持；孤立的系统可能不需要立即修补；暴露在互联网上的 OT 可能需要优先进行修补。 |
| 安全变更测试不充分 | 未经测试就部署的硬件、固件和软件的修改，可能会影响 OT 的正常运行。应制定记录程序来测试所有更改的安全影响。实时运行的系统不应该用于测试。系统修改的测试，可能需要与系统供应商和集成商协调。 |
| 远程访问控制不佳 | 需要远程访问 OT 的原因有很多，包括执行系统维护功能的供应商和系统集成商， 或访问地理位置远程的系统组件的 OT 工程师。最小权限的概念，应该应用于远程访问控制。远程访问功能必须得到充分控制，以防止未经授权的个人获得访问权限，或授权的个人获得对 OT 的过多访问权限。 |
| 使用不良配置 | 配置不当的系统，可能会打开不必要的端口和协议。这些不必要的功能可能包含增加系统整体风险的漏洞。使用默认配置通常会暴露漏洞和可利用的服务。应检查所有设置。 |
| 未存储或备份关键配置 | 当发生意外或攻击者发起的配置更改时，应提供用于恢复 OT 配置设置的程序，以维持系统可用性并防止数据丢失。应制定记录程序来维护配置设置。 |
| 便携式设备上的数据不受保护 | 当敏感数据（例如密码、拨号号码）以明文形式，存储在丢失或被盗的便携式设备（例如笔记本电脑和移动设备）上时，系统安全可能会受到损害。保护需要政策、程序和机制。 |
| 使用供应商默认密码 | 大多数供应商默认密码很容易在供应商产品手册中发现，对手也可以获取这些手册。使用默认密码会大大增加 OT 漏洞。 |
| 密码生成、使用和保护不符合政策 | 必须遵循密码政策和程序才能有效。违反密码政策和程序，可能会增加 OT 漏洞。 |
| 应用的访问控制不充分 | 访问控制必须与组织为其人员分配职责和权限的方式相匹配。指定不当的访问控制，可能会导致 OT 用户拥有过多或过少的权限。下面举例说明了每种情况：<ul><li>配置了默认访问控制设置的系统，赋予操作员管理权限；</li><li>系统配置不当导致操作员无法在紧急情况下采取纠正措施。</li></ul> |
| 数据链接不当 | OT 数据存储系统，可能会链接到非 OT 数据源。数据库链接就是一个例子，他允许一个数据库（例如，历史数据）中的数据，自动复制到其他数据库上。在配置不当时，数据链接可能会产生漏洞，并可能允许未经授权的数据访问或操纵。 |
| 恶意软件防护未安装或未更新 | 安装恶意软件（即 malicious software）属于一种常见的攻击。恶意软件防护软件（例如防病毒软件）应在动态环境中保持最新状态。过时的恶意软件防护软件和定义，使系统容易受到恶意软件威胁。 |
| 未经充分测试而实施的恶意软件防护 | 未经充分测试而部署的恶意软件防护软件，可能会影响 OT 的正常运行，并阻止系统执行必要的控制操作。 |
| 拒绝服务 (DoS)  | OT 软件可能容易受到 DoS 攻击，从而导致无法对系统资源进行授权访问，或延迟系统操作和功能。 |
| 未安装入侵检测和防御软件 | 事件可能导致系统可用性和完整性丧失；数据的捕获、修改和删除；以及控制命令执行不正确。 IDS/IPS 软件可以阻止或防止各种类型的攻击，包括 DoS 攻击，并且还可以识别受攻击的内部主机，例如感染蠕虫的主机。 IDS/IPS 软件必须在部署之前进行测试，以确保不会影响 OT 的正常运行。 |
| 未维护日志 | 若没有适当且准确的日志，可能无法确定导致安全事件发生的原因并进行充分的取证。 |

## 威胁事件和事件

所谓威胁事件，是指可能因某些威胁源而对运营造成不良后果或影响的事件或情况。 NIST SP 800-30，修订版 1 【[SP800-30r1](./refs.md#sp800-30r1)】, [附录 E](./appendix-e.md)  确定了一组可能潜在影响信息系统的威胁事件。 OT 的属性还可能呈现独特的威胁事件，例如威胁事件如何操纵 OT 流程造成物理损坏。下 [表 21](#t-21) 概述了潜在 OT 威胁事件，并利用针对工业控制系统的 MITRE ATT&CK 模型 【[ATTACK-ICS](./refs.md#attack-ics)】。

<a name="t-21"></a>
**表 21**，潜在威胁事件示例

| 威胁事件 | 描述 |
| :- | :- |
| 控制权被剥夺 | 暂时阻止操作员和工程师与过程控制系统进行交互。受影响的过程在控制权丧失期间，可能仍在运行，但不一定处于预期状态。|
| 控制篡改 | 对 PLC、RTU、DCS 或 SCADA 控制器中的编程指令进行未经授权的修改、更改报警阈值，或向控制设备发出未经授权的命令。这些变更可能导致设备损坏（若超出容差范围）、工艺过早停机（例如输电线路过早停运）、环境事故，甚至控制设备失效。 |
| 伪造报告消息 | 向 OT 系统操作员发送虚假信息，目的是规避检测或破坏过程控制。攻击者可能诱使防御人员和操作员，误以为发生了其他错误，从而转移其对实际问题根源的注意力（即警报泛滥）。 |
| 窃取运行信息 | 攻击者可能为谋取私利，或为未来行动提供情报而窃取运行信息。 |
| 安全性丧失 | 攻击者可能会针对安全系统功能发起攻击并使其失效，以此作为后续攻击的先决条件，或为日后出现的不安全条件创造不受检查的条件。 |
| 可用性丧失 | 攻击者可能会利用恶意软件，删除或加密人机界面（HMI）、工作站或数据库上的关键数据。 |

已有大量运营技术（OT）事件被报告并记录在案。对这些事件的描述有助于说明运营技术领域内威胁源、漏洞及影响的严重性。如 [附录 C.2](#漏洞和诱发条件) 所述，威胁源主要分为四大类：敌对性、意外性、结构性和环境性。通常，事件可能是多种威胁源共同作用的结果（例如，环境事件导致系统故障，操作员对此作出错误响应，进而引发意外事件）。

以下是归入这四类中的部分已报告事件。这些事件还被进一步分为恶意或非恶意、直接或间接两类，以进一步区分 OT 事件的可能原因。

- **M = 恶意，Malicious**。该事件是由某人出于有害目的发起的。发起者可能针对 OT 系统，也可能不针对；可能知晓潜在后果，也可能不知晓；
- **N = 非恶意，Non-malicious**。没有证据表明引发该事件的行为意图造成事故；
- **D = 直接，Direct**。该事件旨在发现、抑制、破坏，或以其他方式影响 OT 系统；
- **I = 间接，Indirect**。该事件被认为并非旨在发现、抑制、破坏，或以其他方式影响 OT 系统。OT 系统因支撑基础设施受到影响而关闭或导致中断。


### 对抗性事件

- **[M][D] 马可尼无线电黑客事件** <sup>9</sup>。1903 年，意大利无线电先驱古列尔莫·马可尼，正准备进行首次公开演示，试图实现从康沃尔到伦敦皇家学会弗莱明教授之间的远程安全无线通信。发明家兼魔术师内维尔·马斯克林破解了该系统，并用摩尔斯电码发送了一条提及 “老鼠” 的滑稽信息。随后，马斯克林在行业期刊 *《电工，The Electrician》* 上发表了关于此次破解的说明；

    > **注**：<sup>9</sup>** 有关马可尼无线电黑客事件的更多信息，请访问 [osti.gov: History of Industrial Control System Cyber Incidents](https://www.osti.gov/biblio/1505628)。

- **[M][I] 伍斯特空中交通通信** <sup>10</sup>。1997 年 3 月，马萨诸塞州伍斯特市的一名青少年，利用连接到该系统的拨号调制解调器，瘫痪了公共交换电话网 PSTN 的部分网络。此次攻击导致控制塔、机场安保、机场消防部门、气象服务以及使用该机场的各航空公司的电话服务中断。塔台的主无线电发射机、控制跑道灯光的另一台发射机，以及管制员用于监控航班进展的打印机均被关闭。此次攻击还导致附近拉特兰镇 600 户家庭和企业的电话服务中断；

    > **注**：<sup>10</sup>** 有关伍斯特空中交通通信事件的更多信息，请访问 [archive.org: Teen hacker faces federal charges](https://web.archive.org/web/20220303041809/http://edition.cnn.com/TECH/computing/9803/18/juvenile.hacker/index.html)

- **[M][D] 马鲁奇郡污水泄漏事件** <sup>11</sup>。2000 年春季，某家开发制造软件的澳大利亚机构的一名前雇员向当地政府申请工作，但遭到了拒绝。据报道，在随后的两个月里，这名心怀不满的员工利用无线电发射器多达 46 次，远程入侵了污水处理系统的控制系统。他篡改了特定污水泵站的电子数据，导致其运行故障，最终造成约 26.4 万加仑的未处理污水排入附近的河流和公园；

    > **注**：<sup>11</sup> 有关马鲁奇郡污水泄漏事件的更多信息，请访问 [theregister.com: Hacker jailed for revenge sewage attacks](http://www.theregister.co.uk/2001/10/31/hacker_jailed_for_revenge_sewage/)

- **[M][I] Night Dragon** <sup>12</sup>。McAfee 报告称，发生了一系列旨在窃取全球石油、能源和石化行业敏感数据的攻击。攻击者窃取了与油气田投标和运营相关的专有运营数据及项目融资信息；

    > **注**：<sup>12</sup> 关于 Night Dragon 的更多信息，已作为 McAfee 白皮书发布，网址为 https://www.heartland.org/_template-assets/documents/publications/29423.pdf

- **[M][D] 伊朗离心机，Stuxnet** <sup>13</sup>。Stuxnet 是一种于 2010 年 7 月发现的 Microsoft Windows 计算机蠕虫，专门针对工业软件和设备。该蠕虫最初无差别传播，但包含一个高度专业化的恶意软件有效载荷，该载荷仅针对配置为控制和监控特定工业流程的特定 SCADA 系统；

    > **注**：<sup>13</sup> 有关 Stuxnet 蠕虫病毒的更多信息，请访问 [wired.com: An Unprecedented Look at Stuxnet, the World's First Digital Weapon](https://www.wired.com/2014/11/countdown-to-zero-day-stuxnet/)

### 结构性事件

- **[N][D] 华盛顿州贝灵厄姆，汽油管道故障** <sup>25</sup>。1999 年 6 月， 237，000 加仑汽油从 16 英寸管道泄漏，1.5 小时后起火，造成 3 人死亡、8 人受伤，并造成大面积财产损失。控制系统无法执行控制和监测功能，加剧了管道故障。就在事件发生之前和事件期间，SCADA 系统表现出较差的性能，导致管道控制器无法发现管道运行异常情况并做出反应。 2002 年 10 月发布的 NTSB 报告中的一项重要建议是，利用离线开发和测试系统来实施和测试 SCADA 数据库的更改；

    > **注**：<sup>25</sup> 有关华盛顿州贝灵厄姆汽油管道故障事件的更多信息，请访问 [http://www.ntsb.gov/investigations/AccidentReports/Reports/PAR0202.pdf](http://www.ntsb.gov/investigations/AccidentReports/Reports/PAR0202.pdf)
